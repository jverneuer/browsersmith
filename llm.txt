# browsercore — LLM Usage Guide

browsercore (npm: `browsersmith`) is a TypeScript HTTP client that impersonates real browsers at the wire level. It produces byte-identical TLS ClientHello, HTTP/2 SETTINGS, and HTTP/1.1 header ordering to Chrome or Firefox. It does NOT execute JavaScript, render DOM, or run a browser engine — it is a `fetch()` replacement for bot-detection evasion and browser-accurate HTTP.

## When to use this library

- Crawling/scraping server-rendered websites that fingerprint via JA3/JA4/HTTP2 signals
- Defeating bot-detection that keys on TLS or HTTP/2 fingerprint (not JS challenges)
- Authenticated API testing with browser-accurate requests
- High-throughput crawling where spawning a full browser is too expensive
- Cookie/session persistence across many requests
- CI smoke tests against bot-protected endpoints

## When NOT to use this library

- SPAs that require JavaScript execution to render content
- Sites using Cloudflare Turnstile / JS challenges / CAPTCHAs
- Tasks needing screenshots, user interaction, or visual inspection
- Sites behind login walls requiring browser-based auth flows
- WebSocket connections (not implemented)
- Production HTTP/3 — it exists only as an experimental opt-in via `crawl({ http3: factory })` with a user-supplied UDP `DatagramTransport` (browsersmith wires no default UDP transport)
- WebGL/Canvas/Font fingerprinting (browsercore does not touch these)

## Quick start

```ts
import { fetch, platform, PROFILES } from "browsersmith";

// One-shot request with Chrome 140 fingerprint.
// The 3rd argument (platform) is required — without it the client throws
// (it has no fallback event/adapter provider).
const res = await fetch("https://example.com", {
  profile: PROFILES["chrome-140"],
}, platform);
const html = await res.text();

// Reusable client with cookie persistence
import { createClient, loadJar, platform, PROFILES, saveJar } from "browsersmith";

const jar = await loadJar("./cookies.json");
const client = createClient({
  profile: PROFILES["firefox-128"],
  cookieJar: jar,
  platform,
});

const page1 = await client.fetch("https://shop.example.com/cart");
const page2 = await client.fetch("https://shop.example.com/checkout"); // sends cookies

await client.close();
await saveJar(jar, "./cookies.json");
```

## Core API

### fetch() — one-shot request
```ts
fetch(url: string, options?: FetchOptions, platform?: Platform): Promise<FetchResponse>
```
Options: `profile`, `headers`, `method`, `body`, `timeoutMs`, `followRedirects`, `maxRedirects`, `cookieJar`, `signal` (AbortSignal). The 3rd `platform` argument (exported by browsersmith) is required in practice — without it the client throws (no fallback adapter provider). Equivalent alternative: build a client with `createClient({ platform })`.

### createClient() — persistent connection pool
```ts
createClient(options?: FetchClientOptions): FetchClient
```
Returns a `FetchClient` with `.fetch()`, `.close()`. Pass `platform` in the options — required (or at minimum `events: platform.events`). Synchronous — do not await it. Reuses connections and replays cookies from `cookieJar` automatically.

### crawl() — multi-URL batch fetcher
```ts
crawl(urls: readonly string[], options?: CrawlOptions): Promise<CrawlResult[]>
```
Await the result array (NOT an async generator — no `for await`). Each `CrawlResult` is `{ url, ok, status?, response?, http3Response?, error? }`; a failed fetch becomes `{ ok: false, error }` and does not abort the crawl. Options: `concurrency`, `delayMs`, `profile`, `cookieJar`, `fetchOptions` (per-request options merged into every call), `timeoutMs`, plus experimental `http3` (a `(host, port) => DatagramTransport` factory you supply — one fresh QUIC connection per URL, no pooling). crawl() wires the platform internally; no `platform` argument needed.

### PROFILES — built-in browser fingerprints
```ts
PROFILES["chrome-140"]   // Chrome 140 — the recommended default
PROFILES["firefox-128"]  // Firefox 128
```
Keys are kebab-case strings — dotted access (`PROFILES.CHROME_140`) is a syntax error; use brackets. These two are the curated starters; the full registry (chrome-120/128, edge-120/128, firefox-120/135, safari-17/18) is reachable via `getProfile(id)` / `listProfiles()`.

Each profile produces the full fingerprint triple: TLS ClientHello + HTTP/2 SETTINGS + HTTP/1.1 header order.

### Cookie jar
```ts
createCookieJar()               // new empty jar
loadJar(path)                   // load from JSON file (standalone function)
saveJar(jar, path)              // persist to JSON (standalone function — not a jar method)
jar.getCookies(url, context?)   // matching cookies
jar.setCookie(raw, fromUrl)     // set from Set-Cookie header
```
RFC 6265-compliant: domain matching, path matching, SameSite enforcement, secure/httpOnly flags, expiration, CHIPS.

## Errors

All errors extend `FetchError` with a `kind` discriminator:

| Error | kind | When |
|---|---|---|
| `FetchTimeoutError` | `"FetchTimeoutError"` | Request exceeds `timeoutMs` (carries `timeoutMs`) |
| `RedirectError` | `"RedirectError"` | Too many redirects or redirect loop |
| `ProtocolError` | `"ProtocolError"` | ALPN negotiation failure / protocol violation |

There are no `ConnectionError` / `TLSError` exports — connection and TLS failures surface as base `FetchError`s with the lower-level error on `cause`.

```ts
try {
  await fetch("https://example.com", { profile: PROFILES["chrome-140"] }, platform);
} catch (err) {
  if (err instanceof FetchTimeoutError) {
    // err.timeoutMs, err.url
  } else if (err instanceof RedirectError) {
    // err.url, err.redirectCount
  }
  // All errors have: err.kind, err.message, err.cause, err.url
}
```

## Patterns for LLM-assisted building

### Crawling a site
```ts
import { crawl, createCookieJar, PROFILES } from "browsersmith";

const results = await crawl(urls, {
  profile: PROFILES["chrome-140"],
  cookieJar: createCookieJar(),
  concurrency: 5,
  delayMs: 200,
});
for (const result of results) {
  if (result.ok) {
    console.log(result.url, result.status);
    const text = await result.response?.text();
  } else {
    console.error(result.url, result.error);
  }
}
```

### Defeating bot detection
```ts
// Rotate profiles to vary fingerprint
const profiles = [PROFILES["chrome-140"], PROFILES["firefox-128"]];
const profile = profiles[Math.floor(Math.random() * profiles.length)];

const res = await fetch(targetUrl, {
  profile,
  headers: {
    "Accept-Language": "en-US,en;q=0.9",
    // browsercore handles the rest of the header order automatically
  },
}, platform);
```

### Authenticated crawling
```ts
// Step 1: Get cookies via browser automation (Playwright)
// Step 2: Use browsercore for high-volume fetching
const jar = await loadJar("./auth-cookies.json");
const client = createClient({
  profile: PROFILES["chrome-140"],
  cookieJar: jar,
  platform,
});

// All requests now carry authentication cookies with browser-accurate fingerprints
for (const productUrl of productUrls) {
  const res = await client.fetch(productUrl);
  // process...
}
```

## Package architecture

browsercore composes independently published `@browsercore/*` packages:
- `@browsercore/fetch` — the fetch() API
- `@browsercore/profiles` — fingerprint definitions (pure data)
- `@browsercore/cookies` — cookie jar
- `@browsercore/tls` — TLS 1.3 (JA3/JA4 source)
- `@browsercore/http2` — HTTP/2 client
- `@browsercore/http1` — HTTP/1.1 client
- `@browsercore/compression` — gzip/deflate/brotli/zstd
- `@browsercore/crypto` — AEAD, HKDF, X25519, hashing

All packages follow the provider abstraction pattern and are independently versioned.

## Environment requirements

- Node.js >= 26
- ESM only (`"type": "module"`)
- TypeScript >= 7 recommended
